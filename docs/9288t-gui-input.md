# 9288T GUI 键盘输入（T-GUI-KEYS-2）

旧 T 端私有矩阵仅把方向、退出、确定六种键转换到 A 系列扫描码，其他键未实现。
本版仅对 `--target 9288t` 改用系统 GUI 键盘消息；9288、9288S、听说王的路径不变。
这是编译器公共运行库修复，不是针对伏魔记或魔塔的游戏补丁；已有 EXE 必须重新转换。

## 官方用法与接口

沿用 [官方 API 调查](9288t-official-api.md) 中同一 EXE/固件样本：

- 官方窗口过程 `0x02713f22` 接收 `MSG_KEYDOWN (0x10)` / `MSG_KEYUP (0x12)`，
  从 `wParam` 保存扫描码；普通按键处理后同样进入 `DefaultMainWinProc`。
- 官方 `0x027140e4–0x02714142` 等待路径通过 GUI `+0x30` 调用 `GetMessage`，
  并使用 `TranslateMessage` / `DispatchMessage`。没有另猜晚段键盘表项。
- SDK `guiCommon.h` 的 `SCANCODE_POWER_OFF_ON` 是 F12（88），不是游戏退出键。
  游戏退出为 Escape（1）。`MSG_CHAR/SYSCHAR` 的参数是字符，不是扫描码；
  比如 ASCII `X` 恰好也是 88，不能因此触发电源。

运行库处理普通、SYS、DT 三组 KEYDOWN/KEYUP；按下记录到同一个客机 FIFO，
松开只更新 held 状态。所有消息先 TranslateMessage、再 DispatchMessage，
只在本窗口过程采集一次，随后保留默认窗口处理。CHAR/SYSCHAR 不再次入游戏队列，
但不跳过系统分派。电源不入游戏 FIFO。

完整固件实测发现，实体 Shift（K6.4）独自按下不生成普通 KEYDOWN；
Shift+A 则产生带 `lParam & KS_SHIFT == 3` 的 A 消息。因此不能只补扫描码表。
本版保留 GUI 修饰标志，并只读 SDK `c33L05.h` 明示的 `uc_KPORT_K6D`
（`0x000402c4`）第 4 位，为独立 Shift 合成一次 `$28` 边沿。
不切换矩阵行、不写键盘寄存器、不屏蔽中断；其他键仍全部由 GUI 采集。
实体 Shift、GUI Shift 扫描码和组合键标志共用 held 状态，避免同一次 Shift 重复入队。
该单独的只读补充是因为固件没有独立 Shift 消息，不宣称这是 GUI 键盘 API。

另一处实际固件差异是帮助键：按下发 `MSG_HELP (MSG_USER-3 == 0x7fd)`，
松开仍发 `KEYUP(87)`。官方窗口过程已有这个分支；运行库把该通知规范成
同一个 Help 按下状态，不要求固件额外发 KEYDOWN，也不会与普通 Help 扫描码重复入队。

## 映射

| 9288T GUI 键 | A 系列原始扫描码 |
| --- | --- |
| A–Z | 原 A 系列各字母代码（不是 ASCII）；修复 O/P 字符翻译遗漏 |
| 0–9 | `$08–$0f` 为 1–8，`$30/$31` 为 9/0 |
| 空格 | `$36` |
| 上、下、左、右 | `$35/$38/$37/$39`，支持两组 SDK 箭头码 |
| 上翻、下翻 | `$3a/$3b` |
| 帮助 F11 | `$2d` |
| Shift（左、右及物理 Shift/F8） | `$28`，原开发包 `KEY_SHIFT == KEY_ZY`；不是 `$20` |
| 输入法 | `$20` |
| Insert、修改、搜索、删除/Backspace | `$29/$2a/$2b/$2c` |
| 目录、发音 | `$01/$07` |
| 退出、确定/键盘确定 | `$2e/$2f` |
| 电源 F12 | 不转换，交系统 |

## 采集、计时与退出

`HavePendingMessage` 只检查队列，不能代替 IAL 采集。因此安装宿主 GUI timer #2，
周期参数为 1（固件量化约 25 ms），为无输入时进入 `GetMessage` 提供有界唤醒。
每批最多 16 条消息，有待处理消息时提前采集；无消息时按 CTM 间隔进入一次采集。
**此 timer 只服务 GUI，不推进游戏、生成客机 timer 或决定动画帧数。**
客机计时继续用现有 256 Hz CTM 与 A 系列 timer 重装值。

同一 held 键的 OS 重复 KEYDOWN 不再次当成按下边沿。确定、退出、字母等不自动重复；
方向按住约 80 CTM tick 后开始重复，此后最短 20 tick，FIFO 非空时不积压重复移动。
真实松开再按下不被合并，短按可以在绘图期间入队、稍后消费。

启动前及退出后用 GUI timer #1 等待已知 held 键释放，再维持至少 32 CTM tick（125 ms）
和两个本窗口 timer 消息的安静屏障；不修改键盘矩阵端口，不清理全局队列。
原保活 API 核验、task-3 配对及 500 ms 前台保活继续保留。

运行中收到窗口关闭时只设置 stop 标记；正在等待消息/菜单/对话框的 C API 先正常返回，
其原生桥在返回后恢复进入游戏前保存的 SP/DP，安全返回 App_Main 清理资源。
不从 GUI 回调直接跳出仍持有资源的 C 栈。已消费 Quit 时不再等待第二个 Quit。

性能日志标识 `build=T-GUI-KEYS-2`，增加 GUI 输入模式、泵批次、键盘/电源消息、
忽略的字符消息、Shift 边沿与 stop 标记，保留原 guest timer 指标便于真机对照。
`t_gui_raw` 保存首次 16 条及最近 48 条键盘消息：
`CTM tick,message,wParam,lParam,accept`。仅在 RAM 记录，退出时写日志。
启用可选崩溃追踪的 T 构建改用 **Shift+D** 切换日志，普通 D 仍交游戏；
非 T 端现有追踪快捷键不变。

## 验证范围

回归执行生产映射、字符翻译、FIFO 与 GUI 采集头文件，覆盖所有字母、数字、
空格、翻页、帮助、三组 Shift、短按、重复消息、系统电源转交、有限批次、重入保护、
启动/退出释放与 Close/Quit。S1C33 CPU 探针执行实际生成的桥汇编，检查关闭时
C 回调已返回、SP/DP 恢复，同时覆盖内置/外置资源和启动前收到关闭。

2026-10-15 在隔离 NAND 的完整 Dream9288T 固件中实测魔塔标题菜单：
单独 Shift、Shift+A 分别得到一次 `$28`；A 和随后主动按下的 C 各一次，
退出正常返回桌面。全键轮次 26 个字母和 10 个数字各一次，空格、两种翻页和
四个方向各一次，无溢出。最终专用 Help 修复轮次未主动按 C，日志为：
Shift 2 次；A、帮助、空格、上翻、下翻、退出各 1 次；8 次入队、8 次消费，
无 C、无溢出，task-3 已恢复，正常返回桌面。完整自动回归为 359 项通过。
伏魔记最终 1.5×线性构建也通过标题、主菜单、确认、上下键及退出桌面；
日志四次入队和消费一一对应，宿主 task-3 恢复成功。
测试记录保留在工作区 `build/9288t-gui-validation-20261015/`。

电源验证有明确限制：同一模拟器在系统桌面按实体 Power 也不休眠，
不能把这个结果归因于游戏，也不能据此宣称真机电源已经验证。
休眠/唤醒与实际按键体感仍需在用户设备上复测；宿主回归只验证完整系统分派未被截断。
