# 架构与兼容性

## 编译过程

GAM 头校验 → 6502 指令与 CFG 恢复 → C6502 函数/调用识别 → 语义模板提升 →
S1C33 汇编 → 9288 原生运行库链接 → 资源压缩、KF2 图标与名称封装 → 输出校验。

这是 PC 上的离线翻译。编译结果使用 S1C33 原生 call/ret/分支；普通游戏执行不经过
客机 opcode 取指和解释分派器。未知函数和无法链接的调用是编译错误。
动态间接调用仍需要已经恢复的原生目标查找，这不等于逐指令解释。

`compiler/boot.py` 在 PC 上运行参考核心，准备入口初始 RAM、银行映射和寄存器。
`data/boot_reference` 与 `data/runtime` 明确分离，前者绝不作为输入链接到真机 EXE。
输出中仍维护游戏需要的 RAM 与银行语义，不等于恢复出了完整、可读的原游戏 C 源码。

## 两套 ABI

- 生成的游戏代码：R4=A、R5=X、R6=Y、R7=SP、R8=延迟 N/Z、R9=P、R10=软件栈、R14=RAM。
- 9288 SDK：R6–R9 传参、R4 返回、R15 保留固件 DP。

构建会编译小探针，拒绝 P/ECE ABI 和使用 SP 的不安全 call/ret delay slot。
不要直接换成未打补丁的 S1C33 LLVM，也不要混用 9588 SDK。

## 文件与运行边界

应用资源通过包路径定位，工作产物写到用户工作目录，避免写入 Program Files 或源码。
源码与冻结版都通过 `task_command` 进入受限的 worker 模块白名单。冻结版调用
`A9288-CLI.exe`，不把 `sys.executable` 当成 Python 解释器执行脚本，也不会递归弹出 GUI。

GUI 后台线程只收集消息，不直接操作 Tk 控件。主线程处理进度/按钮状态；取消只作用
于本次拥有的进程树。编译错误或体积超限不替换旧 EXE；最终 EXE 最后原子替换。
ELF/MAP/报告与 EXE 并非跨文件事务，磁盘错误时应检查最终报告哈希。

## 已知限制

- 当前针对已识别的 C6502 ABI、固件布局与入口组织；不是任意 6502 二进制翻译器。
- 入口之外的间接调用、代码/数据混排和手写汇编可能超出恢复能力。
- 共享 API 适配是兼容实现，并非所有固件功能均等价完成；特别是帮助、声音等功能
  的覆盖需要继续扩大。拒绝未知入口并不能证明所有已知入口都完整实现。
- 当前 KF2 小于 1 MiB；真实可用堆内存、资源布局和游戏自身需求仍可能造成失败。
- GUI 成功提示只证明编译/链接/输出校验，不代表所有剧情、存读档或真机性能通过。
- 源码版的完整原生构建已在 Windows 验证；Linux CI 检查 Python/纯 C 单元逻辑，
  不将其描述成已经验证的 Linux 9288 工具链分发包。

独立拆分时，《魔塔之怀旧终曲》的原生 payload 与拆分前已验证版本逐字节一致。
此验证不依赖把游戏放入 Git；用户提供的私有集成输入始终只保留在本地。
