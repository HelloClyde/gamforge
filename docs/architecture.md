# 架构与兼容性

## 编译过程

GAM 头校验 → 6502 指令与 CFG 恢复 → C6502 函数/调用识别 → 语义模板提升 →
S1C33 汇编 → 9288 原生运行库链接 → 未压缩资源、图标与名称封装 → 输出校验。

## 未压缩资源与内存归属

- 内嵌 GAM 保留原字节及原偏移，放在 EXE 的可写 `.data` 段。系统载入后，
  `state.game` 直接指向该区域；不再申请、复制或解压整份 GAM。原指令仍只是
  可读取的数据，游戏执行的是 PC 编译得到的 S1C33 代码。
- 保留可写性是必要的：部分游戏会写 GAM 地址空间中的数据。写入只改本次
  载入的 RAM 映像，不改磁盘 EXE；退出时不能对该指针调用 `free`。
- 每个加载映像只运行一次 `App_Main`。从桌面重新启动由系统重新载入 EXE；
  不支持在同一已修改的映像中直接再次 `prepare` 来恢复 GAM 初值。
- 32,832 字节启动快照以原字节内嵌，启动时复制到 `.noinit` 工作 RAM，
  不解压、不占动态堆。它与整份 GAM 副本不同，是游戏需要的可写工作 RAM。
- 外置 RES 同样是未压缩原字节，保留 4 KiB 分页、128 KiB 缓存及写时复制。
  缺页仍有磁盘读取成本，不是无条件快于内嵌资源；不计算运行时 CRC。
- EXE 超限会明确失败并提示外置模式，绝不静默压缩或突破已配置的上限。

旧版内嵌资源只在启动时解压一次，不会在游玩期间反复解压。因此本改动
消除的是启动解压和整份资源堆副本，不能据此宣称游玩帧率会成倍提升。

本轮验证（2026-10-16）：未压缩《伏魔记》9288T EXE 为 1,587,957 字节，
完整固件模拟器进入菜单、开场文字及“小蝴蝶”剧情画面。GAM 所在 ELF 段为
可写、不可执行 `.data`，与原文件逐字节一致；本轮没有验证全流程、正常退出
后重开或真机性能。结束测试后已恢复模拟器原应用文件并下载核对一致。
《仙剑四》内嵌模式的预计完整 EXE 为 2,701,941 字节，超上限 80,501 字节，
正确拒绝且不发布输出；未压缩外置模式生成 737,633 字节 EXE 与 1,968,064
字节 RES，仅完成编译和数据一致性检查，尚未作运行验证。
实际仓库的资源、运行库、编译器、机型、转换和大小边界回归共 139 项通过；
随后增加旧 MAP 不误导链接错误的测试，资源专项 7 项通过。

这是 PC 上的离线翻译。编译结果使用 S1C33 原生 call/ret/分支；普通游戏执行不经过
客机 opcode 取指和解释分派器。未知函数和无法链接的调用是编译错误。
动态间接调用仍需要已经恢复的原生目标查找，这不等于逐指令解释。

`compiler/boot.py` 在 PC 上运行参考核心，准备入口初始 RAM、银行映射和寄存器。
`data/boot_reference` 与 `data/runtime` 明确分离，前者绝不作为输入链接到真机 EXE。
输出中仍维护游戏需要的 RAM 与银行语义，不等于恢复出了完整、可读的原游戏 C 源码。

## 两套 ABI

- 生成的游戏代码：R4=A、R5=X、R6=Y、R7=SP、R8=延迟 N/Z、R9=P、R10=软件栈、R14=RAM。
- 9288 SDK：R6–R9 传参、R4 返回、R15 保留固件 DP。

构建会编译小探针，拒绝 P/ECE ABI 和使用 SP 的不安全 call/ret delay slot。
不要直接换成未打补丁的 S1C33 LLVM，也不要混用 9588 SDK。

## 文件与运行边界

应用资源通过包路径定位，工作产物写到用户工作目录，避免写入 Program Files 或源码。
源码与冻结版都通过 `task_command` 进入受限的 worker 模块白名单。冻结版调用
`GAMForge-CLI.exe`，不把 `sys.executable` 当成 Python 解释器执行脚本，也不会递归弹出 GUI。

GUI 后台线程只收集消息，不直接操作 Tk 控件。主线程处理进度/按钮状态；取消只作用
于本次拥有的进程树。编译错误或体积超限不替换旧 EXE；最终 EXE 最后原子替换。
ELF/MAP/报告与 EXE 并非跨文件事务，磁盘错误时应检查最终报告哈希。

## 已知限制

- 当前针对已识别的 C6502 ABI、固件布局与入口组织；不是任意 6502 二进制翻译器。
- 入口之外的间接调用、代码/数据混排和手写汇编可能超出恢复能力。
- 共享 API 适配是兼容实现，并非所有固件功能均等价完成；特别是帮助、声音等功能
  的覆盖需要继续扩大。拒绝未知入口并不能证明所有已知入口都完整实现。
- 9288T 完整 EXE 最大 2.5 MiB（2,621,440 字节，含 KF2 头和图标），该扩展为实验性、
  尚未经真机验证；其他目标保持完整 EXE 小于 1 MiB。链接上界还包括 BSS/noinit；
  真实可用堆内存、资源布局和游戏自身需求仍可能造成失败。
- GUI 成功提示只证明编译/链接/输出校验，不代表所有剧情、存读档或真机性能通过。
- 源码版的完整原生构建已在 Windows 验证；Linux CI 检查 Python/纯 C 单元逻辑，
  不将其描述成已经验证的 Linux 9288 工具链分发包。

独立拆分时，《魔塔之怀旧终曲》的原生 payload 与拆分前已验证版本逐字节一致。
此验证不依赖把游戏放入 Git；用户提供的私有集成输入始终只保留在本地。
