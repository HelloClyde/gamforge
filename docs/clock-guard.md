# CTM 回退与 Timer 补算防护（CLOCK-GUARD-1）

## 真机证据

三国霸业 BLIT-RAM-BANK-1 会话（141.773 秒）记录：

- `timer_update_max_gap_ticks=4294967295`，即无符号的 −1 tick。
- `timer_steps=37285790`；单个采样间隔产生 37,282,726 个 Timer 事件。
- `key_scan_max_gap_ticks=1236`，相当于 4.828 秒的扫描空档。

旧代码直接计算 `elapsed = now - timer_clock`，随后每 65,536 tick 补算一轮。
输入 `0xffffffff` 会执行 65,536 轮；以该游戏 reload=166、number=50
重放可产生约 3,728 万个消息，与异常日志相符。
软件下溢漏洞已确认；仅凭这份日志不能断定硬件倒退来自哪一次分频器/日历读取。

## 通用修复

1. CTM 快照在日历读取前后采集分频器；期间若回绕、日历字段变化或字段非法，重读。
2. 已接受读数与候选读数采用 32 位模数差比较。负差不提交，最多尝试四次，失败即返回上次有效值；不忙等。
3. Timer 单独拒绝最高位为 1 的时差，保持基准、分数、剩余周期、客机 RAM 和 pending 状态不变。
4. 合法正时差保留完整推进，不通过丢帧、修改延时、缩短动画参数掩盖异常。
5. 将 `chunk*10000/256` 分成整秒和分数计算；每块最多 `0x04000000` tick，全部中间值可用 32 位表示。
   对任何可接受间隔最多计算 32 块，普通间隔仍只计算一块，无新增 64 位运行库依赖。

合法的 `0xffffffff → 0` 回绕仍按 +1 tick 处理。区分正负的前提是两次观测
间隔小于 `2^31/256` 秒（约 97 天）；不支持游戏运行中手动将硬件日历调回过去。
这不是把时间锁定在数值最大值上，也不是将所有大间隔设成零。

## 新增日志

- `clock_backward_samples`：被拒绝的原始候选数，四次重试可能计为四个样本。
- `clock_max_backstep_ticks`：最大原始回退量。
- `clock_snapshot_retries`：日历/分频器快照不一致或字段非法的次数。
- `clock_retry_exhausted`：单次读取四次失败、沿用上次有效值的次数。
- `clock_forward_wraps`：正常 32 位计数回绕次数。
- `clock_backstep`：最多保留最近八项 `{seq,raw,previous,backward_ticks}`。
- `timer_backward_rejected`：Timer 第二层保护次数；时钟层正常拦截时此值应仍为零。
- `timer_advance_chunks` / `timer_advance_chunks_max`：实际补算总块数/单次最大块数。

已有 `timer_burst_max` 仍表示单块产生的消息数，不是送达次数或画面帧率。
超长正间隔的块变大，因此该项不适合与旧版超长间隔的分块峰值直接比较。

## 验证

- 全量 85 项测试通过（启用 8.BIN、E.BIN 的固件等价测试，无跳过）。
- 新增 9,900 组正间隔组合，与宿主 64 位数学参照比较 IRQ、消息、计数、分数、剩余周期及客机 RAM。
- 故障测试覆盖 −1 tick、重复/持续倒退、重试耗尽、日历非法/跨秒、32 位回绕、关闭 Timer 和长间隔上限。
- 对最终三国霸业 ELF 的 `native_update_timer` 注入 `now=baseline-1`：
  只增加一次拒绝计数，客机 RAM 和全部 Timer 状态不变，未生成事件、未补算。
- 模拟器检查三国霸业主菜单及短按切换；伏魔记进入地图、方向键、系统菜单及退出。
- 两款游戏的 `game-combined.o` 与 BLIT-RAM-BANK-1 逐字节相同；改动只在通用运行库。

模拟器用于功能和机器码故障验证，不用于宣称真机提速比例。仍需真机复测偶发卡顿与按键响应。
