# KEY-CHECKPOINT-1：计算期间捕获短按

## 真机证据（2026-09-07）

KEY-MATRIX-1 的伏魔记会话长 41156 / 256 = 160.766 秒。
117 次入队按下边沿 + 70 次入队连发 = 187 次消费，队列峰值 1、溢出 0。
双样本不一致、动作复核拒绝和动作抖动均为 0。
因此本次日志**没有支持“双采样过滤了右键”的证据**，不应放宽防串键规则。
稳定阶段丢弃的样本没有计数，不能据此证明硬件没有任何电气毛刺。

18296 次扫描的平均间隔约 8.79 ms，但最大空档为 148 tick = 578.125 ms。
平均频率不能证明不会漏掉短按；一次完整按下/松开可能落在空档内。
用户没有提供发生漏检的精确时间，旧日志也没有分键明细，因此尚不能确认：
究竟是未采集，还是交付了 Right、但游戏当时不处理移动。

## 修改范围

- 现有完整 C bridge 每 32 次调用执行一次 capture 检查，仍用硬件时钟门限限频。
- 内存复制、填充的长循环每跨过一个 128 字节边界检查一次。
- 只扫描、更新私有 FIFO；不消费，不调用 GUI/键盘 SDK，不递送客机 Timer。
- 保留 KEY-MATRIX-1 的行稳定、双样本和动作独立复核。
- 不改按键映射、动作去抖、连发、退出清理、游戏代码、计时或等待参数。
- NATIVE-ALU-1 的快速汇编 leaf 保持不变；新检查点只进入已有 C 桥接现场。

这是按工作量设置的合作式检查点，**不是 32 ms 的时限保证**。纯原生循环、
同步 SDK 调用、其他未打点路径仍可能造成空档，须根据新真机日志继续定位。
每次扫描有实际成本，不能在没有真机对照之前宣称性能不变或漏键已彻底解决。

## 日志

构建 `KEY-CHECKPOINT-1` 使用原 PERF 5，关闭 OTHER-PROFILE 重采样。
新增固定诊断存储约 1.65 KiB，不逐帧分配、不在游戏过程中写日志。

- `key_bridge_calls` / `key_checkpoint_checks` / `key_checkpoint_scans`：
  现有完整 C 桥次数、每 32 次检查数、检查实际触发的扫描数。后两者不同，
  因同一 CTM divider tick 内重复检查会直接返回。
- `key_code,code,edges,repeats,consumed`：每个出现过的键的累计计数。
  十进制 57=Right、55=Left、53=Up、56=Down、46=Exit、47=Enter。
- `key_gap_bins`：扫描间隔 <=4、5–8、9–16、17–32、33–64、65+ tick。
- `key_gap,seq,end_tick,gap,previous_scan_last_bridge,current_last_bridge,row7`：
  最近 8 个 >16 tick 的空档；桥 ID 只是两端最近进入的桥，**不是整个空档的耗时归因**。
  ID 以本次生成的 `c6502_native_bridge_ids.h` 为准，4294967295 表示无先前桥。
- `key_event,seq,tick,code,kind,queue_depth_after`：最近 32 条入队/交付事件；
  kind 0=按下入队、1=连发入队、2=非阻塞查询取走、3=等待查询取走。
  入队时间为产生边沿的扫描开始时间，交付时间为取走后读出的硬件时间。
  3 也包括对话框的私有等待，不特指 GuiGetMsg。
- `*_trace_overwritten`：环形记录中未保留的早期条数；不是按键队列丢键。

累计 counts 包含整个会话，环形事件只保留最近记录。消费表示运行库已把键值
交给查询调用者，不代表游戏一定移动了一格，也无法统计完全未被扫描到的物理按下。

## 回归

- 完整 82 项测试、Ruff 和 diff check 通过。
- 受控 148 tick 无游戏查询实验：没有检查点时漏掉期间的短按；已有 C 调用每
  tick 32 次时，新代码捕获两次独立 Right，松开后查询可各取一次，无提前消费。
- 保留矩阵滞后、动作毛刺、真实组合键、长按/连发和启动键基线测试。
- 对实际复制/填充 case 检查零长度、未对齐、128 字节边界与 16 位地址回绕，
  输出逐字节相等；未增加源读取、越界写入或改变参数含义。

模拟器用于功能回归，不用于推断真机扫描延迟或速度。真机低概率症状待复测。
