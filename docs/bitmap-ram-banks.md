# BLIT-RAM-BANK-1：普通 RAM bank 位图误退到逐像素路径

## 真机现象与证据

2026-09-07，用户反馈三国霸业主菜单严重卡顿、按键基本无响应。
日志为 `KEY-MATRIX-1`，游戏 622,874 字节，会话 18,942 tick / 256 = 73.992 秒。

- 61 次 SysPicture 共 12,980 tick，占独占总耗时的 68.525%；单次平均 831.20 ms。
- 61 次调用全部 `picture_ordered_calls`，行融合和直接/暂存源计数均为 0。
- `mapped_lcd_bytes=931104` 恰为 `61 * 159 * 96`：每个像素都更新一次显存字节。
- 图像提交间隔为 230–399 tick（约 0.90–1.56 秒）；这不是 LCD vsync 帧率。
- 42 次入队边沿 + 5 次连发 = 47 次消费，队列无溢出、无不稳定样本或动作拒绝。
  因此不能将现象简单描述为键盘全没采到；消费也不证明游戏一定处理了该键。
- 最大键盘扫描空档 91 tick（355.47 ms），仍是另一个短按风险。

后续 KEY-CHECKPOINT-1 增加扫描检查点，但没有修复这里的绘图退化。
本轮在该版本上修正公共地址解析，不改输入和 Timer 规则。

## 定位

独立 S1C33 模拟器读取实际适配器调用参数：

```
SysPicture(x0=0, y0=0, x1=158, y1=95, picture=0x4800, flag=0)
bank[4] = 4
physical = bank[4] * 4096 + 0x800 = 0x4800
size = 20 * 96 = 1920 bytes
```

这是物理 `$4800..$4F7F` 的离屏 RAM，与 LCD 折行存储的 `$0400..$1000` 范围不重叠。
旧 `picture_source_disjoint()` 只要发现 bank 编号小于 8 就拒绝行融合；
旧 `picture_direct_source()` 也不解析 bank 窗口内的普通 RAM 指针。
因此这里错误地落入逐像素源读取、遮罩、通用显存写入和 2× 扩展。

## 通用修改

1. 按虚拟页拆分完整源区间，计算每段真实物理区间。
2. 只有与保守 LCD 包络重叠的 RAM 别名才拒绝融合，不再把所有低编号 bank 当显存。
3. 连续且 LCD-disjoint 的 RAM bank 区间直接返回 `ram + physical`。
4. 对不连续但各段均安全的 bank，保留逐字节取源到 20 字节行缓冲，再融合输出。
5. 对真实显存重叠、虚拟 DATA/I/O、16 位地址回绕和单字节固件特殊遮罩，保留旧顺序。

关键边界：

| 虚拟源 | 映射 | 处理 |
| --- | --- | --- |
| `$4800` | bank 4 → 物理 `$4800` | 安全 RAM 直接指针 |
| `$4800` | bank 0 → 物理 `$0800` | LCD 重叠，保留旧路径 |
| `$4000` | bank 1 → 物理 `$1000` | 特殊 LCD 字节，保留旧路径 |
| `$4001` | bank 1 → 物理 `$1001` | 区间不越界时允许 RAM 快路径 |
| `$4FF8` 跨页 | RAM bank 4 → RAM bank 2 | 安全但不连续，逐字节暂存源 |
| `$4FF8` 跨页 | RAM bank 4 → RAM bank 1 | 下一页含 LCD 字节，保留旧路径 |

bank 窗口调用的是 `physical_read()`，不是虚拟 DATA 寄存器读取；两者不可混淆。
全区间证明仍每次调用执行，不跨调用缓存 bank 状态。
没有硬编码三国游戏名、大小、指纹、资源地址，没有改 GAM 逻辑，也没有新增图片缓存。

## 工作量与验证边界

159×96 整图由 15,264 次逐像素显存更新降到 1,920 字节更新 / 96 行，
宿主 framebuffer 输出为 15,360 字节。**这不是测得的 7.95 倍游戏速度**。
真正的绘图时间和菜单端到端延迟需真机同场景复测。

- 全部 82 项回归、Ruff、diff check 通过。
- 原有独立像素/字节 oracle 增加 `$4800`、跨 RAM bank、LCD bank 别名等源，
  共 1,440 组源/矩形/flag 差分；比较整片 RAM 和 framebuffer，而非仅截图。
- 单独验证实际 159×96 `$4800` 输入的整 RAM 等价、96 行、1,920 次字节更新和
  15,360 字节宿主输出；零长度、页边界、RAM 尾部与回绕有专门断言。
- 原固件字形/图片/保存恢复等价测试继续通过。
- 最终三国 EXE 在模拟器中 39 次 SysPicture 对应 3,744 行、74,880 源字节，
  `picture_ordered_calls=0`；修复前同路径全为 ordered、行融合为 0。
- 主菜单修复前后画面一致；60 ms Right 短按改变选择。模拟器计时不用于性能承诺。

复测请看 `build=BLIT-RAM-BANK-1`、`picture_direct_bytes/lcd_span_rows` 非零，
并比较整屏 `sample.draw_ticks` 与之前的约 212–216 tick。
如仍存在无响应，再通过分键入队/消费和空档记录定位，不通过重复投递按键掩盖问题。
