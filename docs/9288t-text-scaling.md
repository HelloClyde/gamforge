# 9288T：图片滤波缩放，文字独立点阵

选择 `--target 9288t --display-scale 1.5x-linear` 即启用。GUI 中显示
“图片四灰阶线性 · 文字清晰点阵”。1×、最近邻 1.5× 及其他机型不受影响。

若线性画面偏软，选择 `--display-scale 1.5x-sharp`（GUI 的“四灰阶锐利缩放”）。
它保留同样的 239×144 画面与独立文字层，图片改用像素面积覆盖，不做额外锐化遍历。
从 v1.4.0 起，`1.5x-sharp` 为 9288T 默认模式；旧的 `1.5x-linear`、1× 和最近邻仍可选。
GUI 保留已有合法选择，其他机型的默认显示不变。

## 锐利模式

精确 3:2 放大时，每两个源像素映射成“原像素、两者混合、原像素”。
横纵方向先合并覆盖面积，最后一次量化为四灰阶。原双线性的边缘会向相邻像素
扩散，新模式只混合目标像素实际覆盖的源像素，细线有实心黑核，不附加模糊光晕。
代价是像素轮廓更明显；1.5 倍不是整数缩放，无法同时满足所有笔画等宽和完全无灰边。
原生 24 点文字层不变，图片中的艺术字仍按图片处理。

两种滤波在编译期选择，不增加运行时滤波分支。初版均采用 12 KiB 查表；
2026-10-16 的锐利专用内核已缩为 3 KiB，线性模式仍保留原表。
锐利模式还省去了左右邻字节的外溢更新。
2026-10-15，对实际编译的 S1C33 对象做交替纹理测试（空文字层），
两种模式分别逐字节核对独立参考实现：

| 操作 | 原线性 CPU 周期 | 锐利 CPU 周期 | 减少 |
| --- | ---: | ---: | ---: |
| 屏幕核验 | 97,308 | 97,308 | 0% |
| 全屏逐行绘制 | 578,328 | 564,886 | 2.3% |
| 小块逐行绘制 | 26,963 | 21,347 | 20.8% |
| 全屏 SysPicture | 347,795 | 341,027 | 1.9% |
| 小块 SysPicture | 17,958 | 14,916 | 16.9% |

这是 CPU 模型周期，不是真机 FPS，不能等同于整款游戏加速比例。
当日完整回归 407 项通过，包含边界、细线、脏区、文字覆盖、存取屏和屏幕修复。

### 锐利内核与文字层性能优化（2026-10-16）

- 根据 3:2 面积采样的真实依赖拆成单行/双行查表，不再构造交错采样缓冲；
  锐利表与辅助表从 12 KiB + 512 B 减为 3 KiB。
- 一个源行只影响两个目标行，逐行写入、批量绘图与屏幕核验均按此缩小 dirty 范围。
- 字形覆盖、清除、反白按字节处理；覆盖计数归零的行立即回到纯图片快速路径。
- 锐利模式先在寄存器中合成文字，再写 shadow 与显存；不再先写图片后重新写文字。
  32 位对齐部分一次写 4 字节，边缘使用字节写。字体缓存容量和游戏数据均未改变。

对交替纹理执行 9 次减去 1 次，排除启动成本；使用实际生成的 S1C33 `runtime.o`，
不是主机 C 代码。文字场景预热固定字模缓存，不含固件首次生成字模的开销。
8 个场景同时通过独立逐像素 oracle，并与原锐利版最终 framebuffer SHA256 一致。

| 操作 | 原锐利 cycles/op | 优化后 cycles/op | 周期减少 |
| --- | ---: | ---: | ---: |
| 屏幕核验 | 97,308 | 97,308 | 0% |
| 整屏逐行 | 564,886 | 252,595 | 55.3% |
| 小块逐行 | 21,347 | 12,907 | 39.5% |
| 整屏 SysPicture | 341,027 | 208,247 | 38.9% |
| 小块 SysPicture | 14,916 | 11,614 | 22.1% |
| 24×24 中文 | 76,886 | 47,434 | 38.3% |
| 12×24 ASCII | 50,003 | 34,075 | 31.9% |
| 文字被位图部分覆盖 | 139,176 | 72,824 | 47.7% |

复现：`scripts/benchmark_9288t_framebuffer.py --calls 9 --display-scale 1.5x-sharp
--changing-input --include-tiles --include-pictures --include-text`，另指定工具链、CPU 模拟器、
对应 `runtime.o` 和输出目录。它不测整游戏 FPS，也不代表实机外部 RAM 等待或首次字模读取。

伏魔记 EXE 从 1,031,877 减至 1,026,765 字节。日志标记为 `sharp_kernel_version=2`、
`text_render_version=2`；修正锐利模式原来误报的滤波字段，现为 `display_filter=area_4gray`。
完整宿主回归 419 项通过（取消转换的进程终止测试单独在沙箱外运行）；另 1 项可选
1× S1C33 图片测试因未配置对应 1× 对象跳过，本轮 8 项实际锐利 S1C33 场景均已执行。

## 显示与兼容

- 位图使用 159×96 → 239×144 的四灰阶查表内核，可选双线性或锐利面积采样。
- 系统文字调用保留原来的 8×16 / 16×16 客机字模与排版，同时在显示层绘制
  12×24 ASCII / 24×24 中文。优先使用固件原生 24 点字体；不可用时回退为
  黑白最近邻字模，不让文字经过双线性模糊。
- 图片里已经画好的标题、标牌、艺术字仍是图片，不会猜测文字或 OCR 重绘。
- 不修改 GAM、LIB、资源、客机 LCD RAM 或存档格式。
- 文字层是覆盖掩码和黑白像素两个平面；图片覆盖、局部清除、反白同步更新。
  相邻图片的滤波光晕不会抹掉文字。重复反白可还原，屏幕核验也保留文字清晰度。
- `SysSaveScreen` / `SysRestoreScreen` 和匹配的 `SysPicture(flag=1)` 使用最多四条
  辅助快照。只有缓冲区地址、bank、范围和完整保存字节均匹配才恢复高分辨率文字。
  DATA、MMIO、LCD 别名、回绕地址及非 RAM 不做额外读取。任意自定义内存复制不保证
  保留这种显示元数据，但原始客机位图仍正常显示。
- 屏幕核验若检测到绕过正常绘图接口的客机 RAM 变化，会丢弃全部不可靠的文字覆盖层，
  将 144 个目标行重新绘制为客机位图，避免 24 点字体描边残留。字体缓存和性能统计
  保留，后续正常文字调用仍会生成清晰点阵。已跟踪的图片、文字及局部绘图写入不受影响。

GUI 字体 API 的早期表项保持 SDK 偏移；`SysPrintString` 使用已验证的晚表修正。
`SetHdcFont` 在固件中返回状态，不按 SDK 声明把返回值当旧字体指针；先
`GetCurFont`，完成后以 `SelectFont` 恢复。每个候选字体检查实际高度和字符宽度。

## 内存和性能

固定新增数据约 15.4 KiB：两张 4,320 字节平面、1,920 字节 dirty 标志、
144 字节行覆盖计数、4,864 字节字体缓存，以及四条快照索引和少量控制字段。
四条满屏保存快照合计上限约 41.4 KiB（不含分配器元数据）；内部弹窗还有按区域
临时快照。分配失败只降级显示，不改变原始存屏数据。

字体缓存最多 64 项，命中时不重新调用 SDK 光栅化。整段文字批量刷新。
图片路径使用查表、整数运算、脏区域和空文字层快速路径；一行最后一个文字像素被
覆盖后立即回到快速路径。无浮点或逐像素插值除法；正常更新只处理变化区域，
检测到未知 RAM 变化时才为上述文字降级执行一次全屏重绘。

2026-10-15 实际编译的 S1C33 对象 CPU-only 测试，交替纹理、空文字层，
全部输出与独立逐像素参考一致。相对加入文字层之前：

| 操作 | CPU 周期增幅 |
| --- | ---: |
| 全屏逐行绘制 | 0.89% |
| 全屏 SysPicture | 0.89% |
| 小块逐行绘制 | 3.56% |
| 小块 SysPicture | 3.45% |
| 屏幕核验 | 1.52% |

这不是游戏 FPS，也不包含真机外部 RAM 等待、字体首次读取及固件竞争。活跃文字
合成仍有成本，应结合真机 `NATIVE.LOG` 的 text phase 和新增计数判断：
`text_render_version`、`text_target_glyphs`、`text_composite_bytes`、
`text_font24_cache_hits/misses`、`text_font24_rasterized/unavailable`。

完整 Dream9288T 固件中的魔塔验证已覆盖多页剧情、地图、退出确认和返回桌面。
该次日志记录 328 个目标字形、203 次 24 点字模生成、125 次缓存命中，
`text_font24_unavailable=0`，确认不是仅测试了最近邻回退。
最终伏魔记 EXE 也验证了主菜单、开场引文及小蝴蝶对白，文字层与图片背景同时显示。
宿主测试另覆盖随机局部重绘、两次反白、保存区边界、缓冲区篡改、bank 改变和
分配失败，以及未知 RAM 写入后的无残影降级；完整回归 385 项通过。
实际真机字体和速度仍需对应设备验证。

## 16 灰阶边界

本版本游戏仍为 2bpp 四灰阶。独立的 [16 灰阶探针](9288t-gray16-probe.md)
用于验证 4bpp、LUT 和桌面恢复，不能把 CPU 模拟通过当成物理 LCD、GUI、DMA、
睡眠唤醒全部兼容。通过真机实验前，不把游戏运行库无条件切为 16 灰阶。
