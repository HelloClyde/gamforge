# 游戏存档目录

新转换的程序使用 **`A:\系统\数据\游戏\<原 GAM 文件名（不含 .gam）>\`**。
缺少目录时调用该目标 SDK 的 `fs_mkdir`，从上到下创建目录；所有存档操作都使用
完整绝对路径，不改变进程当前目录，不在创建失败时退回 A 盘根目录。

例如：

```text
A:\系统\数据\游戏\伏魔记\G49NIDX.BIN
A:\系统\数据\游戏\伏魔记\G49TTNNNN.DAT
A:\系统\数据\游戏\魔塔之怀旧终曲\G49NIDX.BIN
A:\系统\数据\游戏\中国象棋\G49NIDX.BIN
```

`G49NIDX.BIN` 是该游戏自己的索引，`G49TTNNNN.DAT` 是存档内容。
`TT`（文件类型）与 `NNNN`（编号）均为十六进制。同一编号、同一文件类型在不同游戏
目录内互不影响，创建、读写、枚举、关闭和删除都使用同一游戏命名空间。
外置 RES 仍放在 `A:\系统\数据\`，不是这个存档目录。

目录使用 **源 GAM 文件名**，不用 GAM 头里可能缩写/带空格的标题，也不用转换时自定义的
程序名。改 EXE 名称、图标、机型、1×/1.5×/线性显示及资源模式不改变目录。
因此重新编译同一名字的游戏仍能使用已有存档；更改源 GAM 文件名则会改变目录。
不同内容但同名的 GAM 按用户指定的名字共用目录，如需隔离请先给源 GAM 不同名字。

路径按 GBK 写入程序。普通名称原样保留；非法字符、无法用 GBK 编码的字符、
结尾空格/点及超长名字经过清理，必要时附加**名字**的短哈希，避免清理/截断后碰撞。
每个游戏目录组件最多 60 个 GBK 字节，不使用游戏内容哈希给不同版本另开目录。
实际路径写入转换 `.report.json` 的 `save_directory`、`save_index` 字段，性能日志也记录它。

## 旧存档与迁移

旧 EXE 仍使用根目录 `A:\G49NIDX.BIN` 与 `A:\G49*.DAT`。
**已有 EXE 必须重新转换，才会使用新目录**；只移动 EXE 不会改变其内置存档路径。
本次不自动修改、删除、导入旧根目录文件。

旧索引没有游戏身份字段，且过去是多个游戏共用的。仅凭文件类型、编号和十字节信息
不能可靠判定归属，自动把整个旧索引导入每个游戏会重新引入串档风险。

- 如果旧索引确实只由一款游戏使用：先完整备份索引和全部 `G49*.DAT`，然后将这一组
  文件**复制**到该游戏报告中的新目录。不要覆盖已经有新存档的目录；保留原件直到确认可读取。
- 如果旧索引已被多款游戏共用：不要把整个共享索引混拷到各游戏；需要先确认具体记录归属，
  再制作对应游戏的索引。无法自动恢复先前已经被其他游戏覆盖的数据。

## 备份和边界

正常退出程序后，直接备份整个 `A:\系统\数据\游戏\<游戏名>\` 子目录即可。
恢复时索引和内容文件必须成组匹配。

启动准备失败、索引未初始化时不写索引；检测到索引截断或格式错误时保留原文件，
禁用该会话的存档创建，避免用空索引覆盖现场或复用旧编号覆盖内容。
目录/文件打开失败由原 File API 返回失败，不会读写别的游戏或旧根目录。

存档索引和数据格式仍是原来的 G49 格式。此次改动不宣称 NAND 写入具备断电原子性，
也不等于验证了所有游戏的存档逻辑；真机仍需验证目录创建、保存、重新打开和读取。
