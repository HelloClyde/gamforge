# 按需崩溃追踪

适用于真机黑屏、重启或某个步骤不再返回，而正常退出的 `NATIVE.LOG` 来不及保存的情况。
这不是修复死机的开关，也不是指令级调试器。

## 转换与操作

GUI 勾选「包含崩溃追踪」，或 CLI 添加 `--crash-trace`。默认不开启记录，不写追踪文件。
进入游戏后，在故障点附近按一次 **D** 开启，再按一次关闭。
9288T 使用物理 D 键，9288 使用 D 键；9288S / 听说王600 点击屏幕右上角 D。
这是转换器通用运行库功能，不依赖特定游戏。带追踪功能的 EXE 会保留 D 键，不传给游戏。

右上角黑色 D 表示已开启；触屏机型的灰色 D 是关闭状态的按钮；E 表示写盘失败，追踪已停止。
按键是在既有扫描点捕获，在恢复 PSR/矩阵寄存器后的安全检查点或下一个 C 桥接边界生效。
阻塞等待输入时不需要额外按一个游戏按键来激活；纯原生忙循环期间不保证能立即开启。
「从启动就开启追踪」/ `--trace-on-start` 可捕获进入游戏后的早期故障，但不覆盖 EXE 加载和资源解压阶段。

开启后，关键图形、内存、文件、对话框及 long / float 运行库调用在执行前后落盘。
普通字节访问、空闲输入查询仅进入最近记录，最多每秒一次检查点，避免空闲时不停写盘。
同步写盘会显著减速、改变 Timer/按键时序，不应拿追踪版开启状态比较性能。
不勾选追踪功能的普通转换结果不包含这些运行时代码、缓冲区和桥接包装。

## 复现后取日志

1. 在即将开始第一场战斗等位置开启追踪，等右上角出现黑色 D。
2. 复现故障；机器重启后连接电脑。
3. 取出 **A:\GAMDBG0.LOG** 和 **A:\GAMDBG1.LOG**，两份都保留、一起提供。
4. 不要再次开启追踪覆盖现场。普通启动、关闭追踪状态下游玩不会覆盖旧快照。

每份文件最多 8 KiB，包含最近 16 个完整 C 桥接或宿主退出事件。两份轮换覆盖，只有最新会话的最近历史，
不是不断追加的大日志。游戏返回写 `status=returned_from_game`，主动关闭写 `status=paused`。
若退出时仍开启追踪，记录继续覆盖输入释放、Timer、DC、资源释放、关窗、Quit、窗口清理、
桌面画面恢复和最终返回。最后正常记录为 `exit_stage=return_to_host`、`exit_step_returned=1`。
需要分析“退出重启”时，请在退出前按 D 开启并保留到退出，不要先关闭追踪。
转换目录的 `.debug-symbols.json`、`.elf`、`.map` 留在 PC，用于地址定位，不用拷到词典。

```powershell
python -m a9288.crash_trace GAMDBG0.LOG GAMDBG1.LOG --symbols 游戏.debug-symbols.json
```

分析器校验完整结束标记和 FNV-1a32 文本校验和，跳过半写入或损坏的快照，
按会话时钟和序号选最新一份。记录数字为十六进制，硬件时钟仍为每秒 256 tick。

## 记录内容与边界

- 调用前 / 调用后的桥接 ID、名称、宿主返回地址与硬件时间。
- A/X/Y、客机 SP、软件栈指针、flags / 延迟 NZ、R0–R3 直接参数、其余共享 ABI 寄存器。
- bank5 / bank9、编译器零页临时量，以及软件栈起始 16 字节。
- 桥接入口的宿主 SP 和观察到的最低 SP；不是 C 函数/固件内部的最深栈位置，也不能单独证明栈溢出。
- 游戏 SHA256、构建指纹、目标机型、写盘统计。分析器拒绝混用同一游戏不同构建的地址符号表。
  栈快照仅在合法常驻 RAM 范围内读取，不触发资源加载。
- 宿主退出事件使用 kind=5/6（进入/返回），ID 是独立的退出阶段编号，不是客机桥接 ID。
  `exit_stage` 给出阶段，`exit_detail` 给出 HWND/HDC 等参数；它们没有客机调用者 PC 或桥接入口 SP，
  相应字段记零，其他客机寄存器只是历史快照，不能当成宿主调用参数。

最后一条是 ENTER 而没有 LEAVE，可以缩小到该调用或其写盘过程；最后是 LEAVE，
说明已返回，后续故障可能在原生游戏代码或快汇编 helper。它不是硬件异常 PC，也不是完整调用栈。
当前不插桩内联原生游戏代码和快汇编叶函数；日志明确标注覆盖边界，不能宣称捕获全部指令。
最后是 kind=5 而没有对应的 kind=6，可缩小到该退出操作或记录过程，仍不等于硬件异常 PC。
退出时的记录不会向已经恢复的桌面重新绘制 D 图标；关闭追踪或新会话的普通启动不改写旧日志。

每次快照都检查 `fwrite`、`ferror`、`fs_update`、`fclose` 的返回值。
两文件轮换可以保留上一份完整快照，但 **不能保证固件重启时 NAND 缓存已物理持久化**，
也不保证文件系统在写入过程中重启不会损坏目录。此保证须由真机进一步验证。
打开文件/写盘失败会停止追踪，不改变游戏返回值；没有接管异常、中断或看门狗。

运行时额外静态存储约 10 KiB（8 KiB 文本缓冲 + 2 KiB 事件环），不占 IRAM，
不按指令分配内存；使用原有 SDK 文件接口和游戏内部矩阵扫描，不引入 GUI 按键消息。
