# EXIT-INPUT-2：退出、动作键与会话日志

## 范围

用户反馈退出后又启动、一次确认触发多次，且前一局性能日志被后一次约 1.91 秒的启动覆盖。
该短日志不代表上一局动画速度。此版本只修改公共运行库；伏魔记、三国霸业的
`game-combined.o` SHA-256 均与 INPUT-FAIR-1 相同，没有改游戏状态、Timer 参数或绘图算法。

## 输入与退出防护

- 确认、退出首按立即进入 FIFO，不增加按下延迟。松开持续 4 个 CTM Tick
  （15.625 ms）后重新允许下一次触发；较短的松开/按下抖动只增加
  `key_action_bounces`，不重新入队。两处物理退出别名合并为一个动作键。
- 方向键保持原有短按及连发策略，未通过清空整个队列来掩盖重复输入。
- 游戏返回后，窗口仍有焦点时等待全部物理键松开，期间继续处理窗口消息。
  等待完成后禁用游戏采样，清空已结束会话的 FIFO，再关闭应用窗口。
- 应用和启动器的退出消息泵均在 **TranslateMessage 之前**过滤
  KEYDOWN/CHAR/KEYUP，避免把结束游戏的确认键交给桌面再次启动程序。
  保留原来的 HWND 过滤、Quit 生命周期、两轮 Timer/DMA 同步和桌面快照恢复。
  不能对启动器整队列调用 ThrowAwayMessages，更不能清理全局消息。

没有在模拟器中自然复现真机接点抖动，因此不能宣称已经证实它是唯一根因。
这项修复覆盖了明确的重复入队路径，真机仍需验证短按、确认及退出行为。
不改变游戏自身“结束游戏返回标题”的控制流；必须区分返回标题与应用重新启动。

## 日志保存

1. 结束会话后写 `A:\NATIVE.TMP`，检查文件错误、update 和 close。
2. 成功后把旧 `NATIVE.LOG` 移为 `NATIVE.BAK`，再把 TMP 移为 LOG。
3. 提升失败时尝试把 BAK 恢复为 LOG；未提升的 TMP 保留用于恢复。

仅保留最新和上一份，不追加无限历史。两个游戏共用这两个名字，采集时应先复制。
FAT rename 不保证断电原子性；不能把此机制描述成断电绝不丢失。
`session_start_clock_tick` 和 `session_end_clock_tick` 区分连续的短启动/长游玩；
它们是回绕的 256 Hz CTM 计数，不是日期字符串。

- 70 项测试通过：既有 ROM 等价测试、短按 FIFO、Timer 公平性，以及新增动作键
  抖动/双退出别名、稳定松开、退出消息过滤、两代日志轮换和提升失败回滚。
- 仅用 app_env_9288 SDK 构建两个游戏；静态检查通过，游戏生成代码未变化。
- 独立伏魔记模拟器进入地图、系统菜单，结束游戏后停在标题，没有自行开始新局。
- 新独立实例从标题退出两次，包含持续按住退出键 1 秒的连续运行测试；均回桌面，
  数字 0 可以切到工具分类，返回后 PSR=0x10、TTBR=0x02000000，空闲 PC=0x58。
- 读取测试 NAND：LOG 9521 字节、BAK 9431 字节，均为 EXIT-INPUT-2 且以 END 结束；
  两组起止计数不同，TMP 不存在，证明短会话没有覆盖唯一一份前局日志。
- 三国霸业完成启动/菜单冒烟；尚未宣称其全流程退出或真机按键抖动已验证。

排查时不要在 S1C33 EXT 前缀执行一半后反复重装断点来下游戏语义结论。
本次有该取证方式造成寄存器/流程异常的迹象；最终退出检查采用单次断点及独立的
无单步连续运行。没有修改模拟器来让目标程序通过。

## INPUT-POLL-1：只在启动和退出使用系统消息（2026-09-06）

用户再次报告退出后的上/确认串键，并要求参照旧 9288 player 的轮询模型。
此前 `native_window_key` 虽然以矩阵为唯一键值来源，仍顺便排空本窗口 GUI 队列，
会调用 HavePendingMessage/GetMessage/DispatchMessage。现在完全移除这条游戏内路径：

- 每次取键仅做矩阵采样和本地 FIFO 的一次消费，非阻塞。
- A 系列 GuiGetMsg 在本地等待 CTM Timer 或 FIFO，不调用 9288 消息泵。
- 游戏期间不创建本窗口 GUI Timer；游戏返回后才启用 Timer #1 处理退出交接。
- 退出过滤补齐 SDK 系统键、桌面键和 KEYOFF。
- 交还桌面前保持本窗口焦点：连续物理松开 125 ms、处理本窗口两次 Timer #1，
  延迟键消息会重新开始安静期。退出阶段必须真正进入 GetMessage，即使 pending 为空；
  只看 HavePendingMessage 的中间版本在模拟器无法推进 Timer，未交付给用户。
- 不清全局消息，不重设固件私有输入状态。原 player 裸机路径还屏蔽系统中断；本次
  不复制其整机中断屏蔽，避免与当前字体/文件 SDK 调用形成未经验证的组合。

70 项测试通过。测试断言游戏取键中任何 GUI 消息 API 调用均失败，宿主已有键盘/退出
消息也不得转换为客机输入；只有物理捕获的数据可被消费。保留原 Timer、公平性、绘图、
输入去抖及两代日志回归。GUI Timer 的启用顺序有额外源码契约检查。

输出位于 `bbk9288-gam4988/build/native-input-poll`，日志标识 INPUT-POLL-1。
