# BBK 9288S 输出

这是独立平台后端，不能只修改 9288T 屏幕常量。翻译出来的游戏代码、C6502 ABI、
银行和资源语义继续共用；平台 SDK、封装、显示和输入按机型隔离。

## 格式与 SDK

- 编译头：9288S SDK 的 `Down_Include`；禁止借用 9288T `include`。
- GNU33 约定仍为 R6–R9 参数、R4 返回、固件 R15 数据指针。
- 文件为 D300 + EXE 双 128 字节头；528 字节原生 LICON 位于 0x100，程序位于 0x310。
- LICON 的 16 字节描述头加两帧 32×32 2-bpp 图像，不含 9288 的额外白框。
- 主头 0x40 是版权字段，程序名称在第二头 0xB0；程序字节数按四字节对齐。
- load address 0x02700000、GNU33 ABI 与应用 RAM 窗口沿用，BSS / noinit 文件尾规则不变。
- SDK `sysConfig.h` 仍有历史 320×240 常量；输出后端不依赖它决定真实屏幕尺寸。

纯 Python 封装无需调用 Windows Apmk；本地官方 Apmk 对照检查必须比较完整字节流，
不能把仅有 D300 魔数或图标可见当作可启动证据。

## 显示

物理 framebuffer 为 0x003C0000，160×240，保持固件原有 2-bpp 模式，行跨度 40，
总计 9600 字节。不更改 LUT、LCD 位深或 IRAM。

上半屏 0..119：游戏可见 159×96，x=0、y=12；160th 隐藏位仅在输出时遮白，
客机 RAM 保持原值。LCD 字节/位图行即时映射到 framebuffer，不等 present 才输出。
整屏刷新和审计必须包含下方键盘，否则固件覆盖恢复会把键盘擦白。
对齐批量写根据目标地址选择半字前缀，S 的 x=0 与 T 的 x=40 对齐不同。

下半屏 120..239：数字、字母、空格、PU/PD（翻页）、四方向、ENTER 和 ESC。
键盘使用内置 5×7 字形，不依赖 GUI 字库；触摸高亮只更新下半屏。

## 输入和退出

实体 GPIO 保持固件配置，读取 K5 0x000402C1 的低四位方向键及 P0 0x000402D1
的 bit4/bit5 退出/确定键，均低有效；不写矩阵行选择寄存器。

触屏使用全屏无标题栏、TOPMOST 窗口的 MSG_LBUTTONDOWN/DBLCLK/UP/MOUSEMOVE，lParam 的两个
signed 16-bit 值为校准后的 x/y。每个事件都更新矩阵快照，即使 DOWN/UP 在同一批。
DefaultMainWinProc 仍接收成对鼠标事件，保留固件捕获和释放流程；不轮询私有 IAL。
ROS33 让出和有界消息泵只在 S 启用，不改 9288/T 游戏内部私有轮询。
游戏时钟继续使用 CTM 256 Hz，不依赖 GUI Timer 推进游戏。
先排空窗口队列；当 FIR7 的 FPT6 因子已锁存，或每 32 批执行一次空闲收集时，
才在空队列上进入 GetMessage。只检查 FIR7 会漏掉已经由固件 IRQ 应答的触摸。
宿主 Timer #2 为此兜底；它不生成客机事件。启动先启用输入并让系统收尾 10 个
ROS33 tick，再释放旧窗口捕获、清除启动触摸的 FPT6 因子、启用 EIR7 bit4 并重新聚焦。
此时游戏输入尚未激活；正式游戏中的 DOWN/UP 仍成对交给默认过程，不丢弃游戏点击。

实体与软键合并后进入同一个 edge/repeat FIFO，不能分别注入同一逻辑键。
短按入队一次，方向长按可重复，确定/退出只在稳定松开后重新触发。
退出仍等待实体/软键松开、过滤残留系统键、销毁窗口、恢复 9600 字节桌面。

## 验证边界

无游戏回归测试包括完整像素对照、软键全屏覆盖/越界保护、GPIO 映射、短点击、
合并输入和确定键长按不连发。私有《魔塔》《伏魔记》用于实际 S1C33 编译检查，
游戏、SDK 和运行产物不提交源码。

本地 SDK Apmk 完整字节流对照通过；9288S 模拟器的独立 NAND 副本已验证
从娱乐菜单启动《魔塔》、上下分屏、实体确定键和触屏确定键进入剧情。
部署后回读 EXE 哈希一致，原始 NAND 哈希不变。模拟器的墙钟触摸持续时间不等于
真机持续时间，短点击 / 长按 FIFO 另有宿主回归测试；尚未验证所有游戏的完整流程。

真机触摸响应、固件版本、长流程存档和速度仍需分别测试；不要用 PC 模拟器速度
替代真机性能结论。所有目标均保持实验性 GAM 兼容范围。
