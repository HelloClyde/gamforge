# 三国霸业启动白屏：32 位移位 ABI 回归

## 现象与定位

用户提供的《三国霸业（正式版）》GAM 为 622,874 字节，SHA-256 为
`c3c01aafdae3b9dbb0f26f27b40c93f2adaa626dc0f8be7a9340d8d07d8a5a76`。
转换可正常完成，但在真机启动白屏；独立 9288 模拟器复现相同现象。

旧 EXE 已经进入游戏消息循环，并调用整屏 `SysPicture`，不是卡在 SDK 加载、
资源解压或程序入口。原生适配日志显示数据 bank 被设置为 `0x3A9`，超出这个
游戏的资源物理范围；读取返回零，绘图源缓冲也全零。

## 根因

C6502 的 `__sl_long` / `__u_sr_long` 与 8/16 位移位 ABI 不同：

- `$20/$21` 指向四字节被移位对象。
- `$23/$24` 指向四字节移位次数对象，不是次数本身。
- 原适配使用 `ram[0x23] & 31`，把指针低字节误当次数，并错误地对超宽次数取模。

本例次数常量位于游戏虚拟地址 `$7D2B`，内容为 14；旧代码读取 `$2B & 31 = 11`。
资源偏移 `0x26A02` 的 bank 计算因此从正确的
`0x275 + ((0x26A02 >> 14) << 2) = 0x299`，变成 `0x3A9`。

## 通用修复

公共原生运行库新增 `c6502_native_long_shift.h`，对照 E.BIN 的 `$DA3D` 和 `$DC0E`
执行顺序实现左右移：

- 按指针读取完整 32 位次数，次数大于等于 32 时输出零。
- 保留“先清空结果临时区，再读取输入”的顺序与重叠语义。
- 零位移保留原操作数指针；非零/超宽路径重定向至 `temp_store + 8`。
- 保留 A/X/Y、C/V/N/Z 等返回状态；不修改游戏代码，不增加游戏名或哈希特判。

新增测试将实际 C 辅助函数与真实固件指令执行结果对照，覆盖 246 组位移、
标志位、临时区地址和输入重叠场景；另有 60 组无需 ROM 的参数用例以及资源 bank
公式回归。配置用户自备固件时，当前全部 54 项测试通过。

## 产物与验证边界

修复后的游戏 EXE 为 983,621 字节，SHA-256：
`0cb9ed0d34dcb40708f8b374a9fc2f1ebad6466dc2cfb7711ccc20d9fa06f692`。
在独立模拟器核对已装载入口与这个 EXE 一致后，验证了主菜单、方向选择、剧本选择、
君主/势力选择、进入大地图、城池操作菜单，以及从系统菜单“结束游戏”返回游戏主菜单；
不以静止截图代替输入响应检查。

这不是全游戏兼容性或真机性能验证。商业游戏及其生成 EXE、RAM 和截图均不随源码发布。
